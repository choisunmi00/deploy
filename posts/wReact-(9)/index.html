섹션 09. useReducer

9.1 useReducer를 소개합니다

  • 9.1

  • useReducer

    • 컴포넌트 내부에 새로운 State를 생성하는 React Hook
    • useState와 다른 점은, 상태 관리 코드를 컴포넌트 외부로 분리할 수 있다는 점
    • 앱 컴포넌트 안에는 UI를 렌더링 하는 코드를 담는 것이 주된 목적.
      상태 관리 코드가 너무 많아지면 주객전도
    • 첫 번째 인수: reducer: 상태를 실제로 변화시키는 변환기 역할
      • 액션들의 타입이 많을 경우 switch 문으로 작성하는 것이 일반적
    • 두 번째 인수: state의 초기값
    • dispatch: 상태 변화가 있어야 한다는 사실을 알리는 함수
      • 액션 객체: 인수로 전달된 객체
        • type: 상태를 어떻게 변화시킬 건지
        • data: 얼만큼

섹션 10. 최적화

10.1 최적화란

  • React App 내부의 최적화 방법
    • 컴포넌트 내부의 불필요한 연산 방지
    • 컴포넌트 내부의 불필요한 함수 재생성 방지
    • 컴포넌트의 불필요한 리렌더링 방지

10.2 useMemo와 연산 최적화

  • 10.2
  • List.jsx 수정
  • useMemo
    • ‘Memoization’기법을 기반으로 불필요한 연산을 최적화하는 React Hook
      • memoization: 반복적으로 수행되는 동일한 연산의 결과값을 메모리에 저장
      • 자매품: useCallback
    • useEffect처럼 deps에 포함된 값이 변경되었을 때에만 콜백함수를 반환
      • 콜백함수에 memoization 하고 싶은 연산
  • filter메서드는 배열 전체 요소를 한 번씩 전부 순회하기에 시간이 점점 오래걸림.
    그러기에 불필요한 호출 방지
    • memoization 통해 연산 기억한 뒤 특정 조건을 만족할 때 수행하도록 처리

10.3 React.memo와 컴포넌트 렌더링 최적화

  • 10.3
  • Header.jsx, TodoItem.jsx 수정
  • React.memo: 컴포넌트를 인수로 받아, 최적화된 컴포넌트로 만들어 반환하는 리액트의 내장 함수
    • 컴포넌트는 Props를 기준(얕은 비교)으로 memoization.
      부모 컴포넌트가 리렌더링 되더라도 Props가 바뀌지 않으면 리렌더링 되지 않는다.
  • 객체 타입에 해당하는 함수 또한 컴포넌트가 리렌더링 되며 새로 생성되면 주소값이 바뀌기 때문에 사실상 다른 값.
    • Props에 전달되는 이벤트 관련 함수도 매번 새로 생성되며 다시 전달되기 때문에 리렌더링 발생.
    • 객체 타입의 값을 Props로 받는 경우 memo 메서드 만으로는 최적화 X
      1. App 컴포넌트에서 함수 자체를 memoization해서 리렌더링되더라도 함수 재생성 방지. (useCallback)
      2. memo 함수 안에 두 번째 인수로 콜백함수를 전달하여 최적화를 커스텀
        • 반환값에 따라 Props의 변화를 판단
  • 고차 컴포넌트(Higher Order Component, HOC): 컴포넌트를 인수로 받아 최적화나 memoization 같은 추가적인 기능을 덧붙여서 기능이 추가된 컴포넌트를 반환해주는 메서드

10.4 useCallback과 함수 재생성 방지

  • 10.4
  • App.jsx, TodoItem.jsx 수정
  • useCallback
    • 첫 번째 인수: 재생성 방지할 함수
    • 두 번째 인수: deps
  • 최적화
    • 언제하는가?: 하나의 프로젝트가 완성이 되었을 때. 1. 기능 구현, 2. 최적화
    • 어떤 것들이 대상인가?: 꼭 필요한 곳에만. 최적화가 효율적으로 동작할 수 있는 곳에만.

섹션 11. Context

11.1 Context란

  • React Context: 컴포넌트간의 데이터를 전달하는 또 다른 방법. 기존의 Props가 가지고 있던 단점 해결.
    • Props Drilling: Props는 부모에서 자식으로만 데이터를 전달(손주에게는 전달 X)하기에 다중전달 해야 하는 상황
    • Context: 데이터 보관소 (객체)

11.2 Context 사용하기

  • 11.2
  • App.jsx, Editor.jsx, List.jsx, TodoItem.jsx 수정
  • Context
    • 프로퍼티 Provider(컴포넌트)
      • Provider로 감싸면 TodoContext의 value값에 담긴 데이터들을 직접적으로 전달 가능
  • useContext: Context로부터 데이터를 꺼내오는 리액트 훅

11.3 Context 분리하기

  • 11.3
  • App.jsx, Editor.jsx, List.jsx, TodoItem.jsx 수정
  • state가 변경이 되며 앱 컴포넌트가 리렌더링 될 때 자식 컴포넌트인 TodoContext.Provider도 함께 리렌더링
  • TodoContext를 분리 (+ useMemo)
    • TodoStateContext: 변경될 수 있는 값
    • TodoDispatchContext: 변경되지 않는 값
      • memoizedDispatch 통해 앱 컴포넌트의 마운트 이외에는 재생성 방지
