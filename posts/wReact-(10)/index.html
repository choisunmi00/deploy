12.2 페이지 라우팅 1. 소개

  • 페이지 라우팅: 경로에 따라 알맞은 페이지를 렌더링 하는 과정
    • 과정: 사용자가 사이트 접속하면, 브라우저(Client)가 서버에 페이지를 요청, 서버는 페이지를 반환하여 브라우저에 전달, 브라우저가 사이트의 페이지를 렌더링
    • 서버 사이드 렌더링: 미리 완성되어 있는 페이지로 응답하는 방식
      • MPA(Multi Page Application) 방식: 서버가 여러 개의 페이지를 가지고 있는 것
        • 페이지의 이동을 빠르게 처리하기 어렵기 때문에 리액트는 이 방식을 따르지 않음
    • 클라이언트 사이드 렌더링: 브라우저에서 직접 자바스크립트 파일을 실행해서 화면을 직접 렌더링(컴포넌트 렌더링)하는 방식
      • SPA(Single Page Application) 방식: 서버가 가지고 있는 페이지는 한 개 + Bundle JS File(Bundling은 Vite가 담당(사실상 React App))
    • MPA 방식의 페이지 이동은 모든 요소를 교체하는 데에 반해, SPA 방식의 페이지 이동은 필요한 요소(컴포넌트)만 교체

12.3 페이지 라우팅 2. 라우팅 설정하기

  • 라이브러리 ‘React Router’: npmjs.com에 등록되어 있는 라이브러리
    • npm i react-router-dom
    • main.jsx에 BrowserRouter 컴포넌트
    • App.jsx에 Routes및 Route 컴포넌트
      • Routes 컴포넌트 안에는 Route컴포넌트만 사용 가능
      • Routes 바깥에 배치된 요소들은 모든 페이지에 렌더링
  • 페이지 구성
      1. ”/”: 모든 일기를 조회하는 Home 페이지
      1. “/new”: 새로운 일기를 작성하는 New 페이지
      1. “/diary”: 일기를 상세히 조회하는 Diary 페이지
      1. ”/*”: Notfound 페이지(*: 와일드 카드)

12.4 페이지 라우팅 3. 페이지 이동

  • 페이지 이동
    • Link 컴포넌트: 링크 이용
    • useNavigate 커스텀 훅: 페이지를 이동시키는 navigate 반환. 버튼 이용

12.5 페이지 라우팅 4. 동적 경로

  • 동적 경로(Dynamic Segments): 동적인 데이터를 포함하고 있는 경로
    • URL Parameter: / 뒤에 아이템의 id를 명시. 변경되지 않는 값을 주소로 명시하기 위해 사용
    • Query String: ? 뒤에 변수명과 값 명시. 검색어 등의 자주 변경되는 값을 주소로 명시하기 위해 사용
  • 동적 경로 설정
    • URL Parameter
      • "/diary/:id"
      • Diary.jsx에서 useParams 커스텀 훅 사용

12.6 폰트, 이미지, 레이아웃 설정하기

  • 폰트 설정
    • public 폴더 아래 위치, index.css에서 @font-face
  • 이미지
    • assets 폴더 아래 위치, import로 불러오기
      • assets 폴더로 Vite가 제공하는 이미지 최적화 적용 가능
        • 배포 시 DATA URI로 이미지 제공. 자동으로 브라우저에 캐싱되어 새로고침 하더라도 다시 불러오지 않게 최적화. (public 폴더의 경우 링크로 이미지 제공, 새로고침 할 때마다 매번 불러옴. 개발자 창 Network 탭의 Size와 Time을 통해 확인 가능) 다만, 이미지가 많을 경우 브라우저가 부담하는 용량도 늘어나기 때문에 때에 따라 public으로 배포하는 것이 유리한 경우도 존재
          • DATA URI: 이미지와 같은 외부 데이터를 문자열 형태로 브라우저 메모리에 캐싱하기 위해 사용되는 포맷.
    • util 폴더로 관리
  • 글로벌 레이아웃: html, body, #root에 전체 레이아웃 설정

12.7 공통 컴포넌트 구현하기

  • 프로젝트 개발 순서 (취향)
    • 페이지 라우팅 - 글로벌 레이아웃 설정 - 공통 컴포넌트 구현 - 개별 페이지 및 복잡한 기능 구현
  • 공통 컴포넌트
    • Button 컴포넌트
      • text, type, onClick을 Props로 전달
    • Header 컴포넌트
      • title, leftChild, rightChild를 Props로 전달

12.8 일기 관리 기능 구현하기 1

  • “일기”라는 형태의 데이터를 관리하는 프로그램
    • home: 일기 리스트 렌더링
    • diary: 일기 상세 조회
    • new: 새로운 일기 작성
    • edit: 기존 일기 수정
  • 까먹었던 edit 페이지 추가
  • useReducer
    • 함수 reducer: 일기 데이터 저장할 state 생성
    • state의 초기값으로 사용할 임시 데이터(mockData) 생성

12.9 일기 관리 기능 구현하기 2

  • onCreate, onUpdate, onDelete
    • dispatch 호출 및 액션 개체 추가
      • id: useRef 및 후위연산자 사용
    • reducer 함수 case에 해당 액션 개체 추가
      • onCreate: 새로운 일기(action.data)를 원본 데이터(…state)에 추가
      • onUpdate: id가 일치했을 때 action.data로 수정, 아니면 item 그대로 반환
      • onDelete: filter를 이용해 id와 일치하지 않은 것들로만 구성
  • Context로 관리
    • DiaryStateContext: 일기 데이터를 공급할 컨텍스트
    • DiaryDispatchContext: 일기를 수정하는 함수를 공급할 컨텍스트
